# Producto, clientes y competencia

## Problema y propuesta de valor

Hipótesis: equipos pequeños pierden tiempo entendiendo fallos y verificando parches. DevGuardian busca reunir diagnóstico, cambios controlados, pruebas y trazabilidad. La propuesta se presenta como asistencia con evidencia, no como garantía de código seguro o reparación universal.

## Segmentos por validar

| Segmento hipotético | Trabajo que necesita resolver | Evidencia a obtener |
| --- | --- | --- |
| Equipos académicos y docentes | Mostrar proceso verificable y aprender QA | Entrevistas y sesión observada con fallo real |
| Equipos pequeños TypeScript | Reducir trabajo manual de diagnóstico/verificación | Medir tarea equivalente con y sin plataforma |
| Consultores de mantenimiento | Entregar evidencia clara de una intervención | Validar formato de informe y disposición a pagar |

No hay clientes, ventas ni tamaño de mercado acreditados por esta documentación. La selección inicial sugerida es piloto académico, por acceso del equipo al contexto; sigue siendo una hipótesis.

## Alternativas existentes: consulta de fuentes oficiales, 2026-10-28

| Alternativa | Qué comunica su fuente oficial | Qué investigar frente a DevGuardian |
| --- | --- | --- |
| [GitHub Code Security](https://github.com/security/advanced-security/code-security) | Análisis y remediación integrados en GitHub | Flujo completo, configuración, cobertura y experiencia del usuario |
| [SonarQube](https://www.sonarsource.com/products/sonarqube/) | Calidad, seguridad y capacidades de corrección asistida | Evidencia, integración, costo y lenguajes del caso concreto |
| [Snyk](https://snyk.io/platform/) | Plataforma de seguridad para desarrollo | Alcance y condiciones del producto elegido |
| Herramientas locales y revisión manual | El usuario puede combinar linter, tests y Git | Si centralizar la evidencia aporta suficiente valor |

Las páginas comerciales describen capacidades del proveedor; no son un benchmark independiente. No se afirma que los competidores solo detecten ni que DevGuardian sea superior. Precios y planes se verificarán al tomar una decisión de compra; no se fijan tarifas ajenas en este informe.

## Diferenciación que debe probarse

Trazabilidad legible para QA, operación por MCP, controles previos a parches y comparación de pruebas en un recorrido sencillo. Validar utilidad real y costo antes de formular una promesa comercial.
